# RAG逐项答全优化验收（2026-10-16）

本轮围绕漏答检测、证据保留和有界补救修改主问答。本次提交整理后的源码、正式前端和公开诊断证据；本机RAR交接包不随源码上传，未发布Release。

## 行为变化

1. 原问题保留完整对象、时期、单位、否定和例外，按明确问句/分号建立问题分项。模型的必要事实计划须绑定全部分项，漏规划时只修正一次；超过8项明确提示分批提问。同一分项内的并列对象仍依赖模型理解。
2. 新增逐项覆盖台账，区分“证据已有但尚未回答”“仍缺证据”“证据冲突”“已回答”。只有最终通过支持检查、且没有被剔除的结论才能计入已回答。原coverage继续表示结论来源绑定比例，不再用它代表原问题答全。
3. 支持证据在上下文打包时按目标预留位置，再填充新召回与不同来源。保留最终实际引用及完整原文，不用截断掩盖超预算。
4. 有证据却漏答时，用已有证据补写一次；证据缺失时，在本轮固定资料、固定版本与剩余预算内定向补查后补写一次。物理检索总上限仍为2次，答全补救总上限为1次，不扩大资料范围。
5. 保留已通过检查的纯文档回答作为下一稿候选，包括旧摘录格式，再走完整引用和模型支持检查。数据库事实不跨查询范围自动携带。新补写内容未获支持时不计入覆盖；仍缺的子问保留缺口或拒答。
6. 空初稿但证据充分时允许一次补写；被拒绝的事实不因重试自动通过。取消、服务失败、完整上下文超限均有独立记录，失败不改写成“资料没有答案”。真实调用、失败、耗时及补救前后台账分别保存。
7. 页面显示“逐项回答 x/y”，展开未解决分项，区分补查和仅补写。它是模型核验后的覆盖记录，不是事实准确率。

## 边界

本轮验证的是答全控制流程和既有功能回归，未测真实千问/其他外部模型的通用语义答全率，未重跑OHR-Bench。明确标点分项不是完整语义解析，模型也可能错误规划或错误判断支持；现有覆盖台账不能取代人工验收。复杂比较、因果、长清单及多跳真实资料仍需独立标注集和真人复核。

本机Windows便携Python下已运行组件及隔离HTTP测试；新RAR解压后的完整桌面启动与真人操作尚未实测，不能视为完整便携运行验收。
