# 复杂表格关系优化验收（2026-10-15）

本轮优化表头、行名与数值的对应关系，覆盖原生 DOCX、原生 PDF、扫描视觉解析及 RAG 证据流。本次提交包含源码、测试、正式前端及公开合成验收证据，不发布 Release。源码和正式前端已同步到本地主目录；本机 RAR 不纳入仓库。

## 改动

- 保留多层列表头、跨行行名、原始合并单元格及单位文字。派生证据绑定数值格、各层列表头、行名和行名标题的真实来源 ID；视觉多表使用独立单元格身份。
- 原生 PDF 从实际格线恢复起点与跨度，去重合并格，保留外置表头。原生表头只沿直接合并层级扩展，避免把文字正文或年份数值误当新表头；纯文字数据仍保留字段对应关系。
- 核对声明行列和单元格矩形的一致性。数字在原图出现，并不证明其逻辑列正确。位置冲突时隔离本表关系；缺少某个必要表头、行名或其角色不明时，只保留其他完整关系。
- 空白不填成 0，不向前填充数值。横跨多个叶列表头、纵跨不同叶行名的共享值不任意分配、不重复计算；原件和未绑定原因保留。
- 表格区域内及跨区域的原始文字保留展示，但不能绕过表格关系核验作为确定证据。人工确认单元格发布新解析；旧解析不变，单纯修改文字不能解除网格位置冲突。
- 带绑定的表格行保持完整切片；超过窗口时保留原件并明确提示打开原表。局部选区不能冒用整行来源，需选择完整行。固定解析中的完整关系经过权威定位、证据绑定后进入模型证据包，模型传入的质量声明不覆盖原件记录。
- 界面区分行列位置冲突、局部网格缺失和跨页续表候选。跨页仅记录候选，不自动合并业务事实；重算时清除失效候选。
- 视觉输出示例改为实际 JSON 数字数组，明确禁止字符串/对象坐标；严格坐标、网格、同区域文字校验继续保留。

## 实际验证

开发样本为一张自行构造的 6×6 表，含两层年份/指标表头、North/South 跨行组、A/B/C/D 行名、15 个非空数值、一个空白和一个明确打印的 0。原生格式测试独立写入 DOCX/PDF，扫描图由另一份合成文件渲染，模糊图为同图高斯模糊版本。

| 流程 | 结果 | 边界 |
| --- | --- | --- |
| 真实原生 DOCX、PDF 解析 | 两种格式均 15/15 精确绑定，4 个数据行 | 逐一核对列路径、行路径及祖先来源 ID；不是 OCR 成绩 |
| 本机 OCR + 千问正式视觉解析，清晰图 | 15/15 精确绑定，0 错误绑定，4 个数据行 | 视觉解析 49.043 秒；本机 OCR 3.377 秒在上次尝试已完成，最终调用复用相同图的观测 |
| 同流程，模糊图 | 11/15 精确绑定，0 错误绑定，3 个数据行 | OCR 3.104 秒、视觉解析 47.616 秒；行名 C 的 OCR 分数 0.68658，相关4个值不进入确定证据 |
| 空白与 0 | 打印 0 保留；空白未变成 0 | 视觉空白格仍待核验，不因缺少 OCR 文字自动证明空白 |
| 真实模型输出离线重放 | 清晰/模糊结果和隔离行为可复现 | 不再次调用模型，不算额外新样本成绩 |
| 人工复核 HTTP 集成 | 核验叶表头恢复局部绑定，旧版本不变；修改文字不能解除几何冲突 | 独立隔离库，未使用个人文档或会话 |

实际调用使用 `qwen3.8-max` 云端视觉服务，密钥只在本机加密保存。没有把密钥、连接记录、运行库、用户上传文件或会话放入证据。开发过程中前两次扫描尝试分别超时及连接失败；后一次清晰图调用成功返回但坐标格式校验失败，修正输出示例后才得到上述最终结果。失败未并入成功计数，也没有在失败后自动重放付费请求。最初清晰图 harness 记录了 978.703 秒的墙钟耗时和超时异常，未捕获分阶段调用轨迹，不能用后续成功耗时覆盖这一异常。

这些是同一合成表及其变体的开发诊断，不是独立 OHR-Bench、中文复杂报表、手写表或完整生成答案准确率。一般表格的业务语义仍需对照原件核验；模糊行名、无框表、错误角色、超长行和跨页业务关系尚不能声称全部解决。

## 回归与使用

仓库副本相关后端 341 项通过；前端 70 项、类型检查和正式构建通过。主目录保留原有其他代码差异，另做后端 236 项、前端 69 项及类型/构建验证；主目录没有仓库新增的 `test_grounding_protocol` 模块，该项不能计作本地主目录已通过。两份正式前端各11个文件与各自构建结果摘要一致。

这是 Windows 本机 Python 组件与前端测试/构建验证；没有完成 Windows 启动器及全界面验收，也没有新增 Mac 实机验收。旧文档需要显式重新解析、重建索引；重启后端后加载新逻辑，旧引用仍固定在旧解析。人工核对模糊行名请选择表格单元格；仅核对普通 OCR 文字不会自动修改表格对应关系。
