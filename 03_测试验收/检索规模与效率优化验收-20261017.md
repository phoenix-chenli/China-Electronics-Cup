# 检索规模与效率优化验收（2026-10-17）

本次提交包含检索规模与效率优化源码、回归检查及公开性能证据。本机 RAR 仅作本地交接，不上传仓库；未发布 Release。完成源码同步后暂停。

## 改动与使用

1. 文档和全库检索改为固定索引内先排序、后按需读取完整切片，避免每次载入全库正文与解析 JSON。查询私有缓存最多 192 个切片、4 MiB 编码 JSON；这不是整个进程内存上限。正文单批读取最多 128 个，返回证据仍最多 8 个完整片段。
2. 向量检索先验证固定范围内全部向量，再按每批最多 512 行精确计算与保留前 30 名。两遍流式扫描代替整库矩阵，未改用近似检索。文档筛选先约束代次，再走嵌入复合索引，不扫描全库其他文档或模型空间。缺损、非有限、零向量、模型空间与输入摘要不符时，在发送问题嵌入之前失败或降级。
3. OCR 拼写容错增加单独的双字符倒排索引，先选最多 400 个候选，仅读取比较所需文字，再读取实际排名中的完整证据。保留原字面，不把纠错猜测写入引用。原关键词 FTS 列与权重保持不变；容错预选及其排序允许变化。
4. 建索引每批最多 16 个切片，批量查询缓存，只为缺失或损坏的输入生成向量，保留有效缓存。任务记录实际复用、生成数量与批次峰值。读取当前解析标识不再顺带载入完整解析体，热身索引避免重复解析。
5. 模型侧目录最多展示 8 份并明确总数；服务端完整白名单和原文不因此截断。检索结果携带权威文档编号，可定向补查目录预览外的来源。真实 HTTP 流程验证了 200 份文档中预览外目标的检索、支持检查和回答；千份目录另有上下文边界检查，未把它称为千份文档端到端测试。
6. 原始文件全量 SHA、固定版本与解析、只读 URI、归档撤销、最终重新核验、取消与期限仍保留。查询私有缓存随请求关闭，不缓存模型判断或跨用户分享正文。真实阶段和候选、读取、向量批次计数保存在 retrieval.execution。

新发布的关键词索引格式为 3，旧固定索引可走兼容路径。重启后端后新查询会刷新关键词发布并采用新路径；旧会话仍固定原版本。切片器、原解析和历史引用未因此改写。当前页面和选区查询保留原有小范围路径，尚未宣称同样的规模收益。

## 实际规模对照

Windows 本机便携 Python；每个版本在独立新进程运行。对照使用 [d2e1efe](https://github.com/phoenix-chenli/China-Electronics-Cup/commit/d2e1efe1dcf98027031fc105be0b07dad3581410) 的改动前源码和实际格式 1 的关键词索引，三个模块已与该提交逐字核对（统一换行）；优化版使用格式 3，固定原始资料完全相同。每份文档最多 250 条自编 Markdown 记录，使用 512 维固定随机向量；问题向量取已知目标向量，旨在核对精确计算与资源开销，不能解释为模型理解能力。外部模型、外部嵌入和重排未调用。

每规模 4 类查询（字面、错拼、向量、指定文档）各重复 3 次，另做一次进程首次查询和预热。下表为 12 次正式测量；候选数、证据数、全文摘要与来源保护未降低。

| 切片数 | 文档数 | 中位耗时：原 → 新 | P95：原 → 新 | 查询进程采样峰值：原 → 新 | 中位加速 |
| ---: | ---: | --- | --- | --- | ---: |
| 1,000 | 4 | 310.38 → 126.54 ms | 378.74 → 187.20 ms | 114.14 → 106.13 MiB | 2.45× |
| 10,000 | 40 | 1696.63 → 494.60 ms | 2132.61 → 563.43 ms | 270.98 → 110.21 MiB | 3.43× |
| 50,000 | 200 | 10544.95 → 3266.05 ms | 11814.92 → 3520.11 ms | 959.68 → 111.54 MiB | 3.23× |

所有规模的关键词和向量前 30 名逐项顺序一致，36 次正式查询的测试目标召回@8 均为 36/36，优化前后相同。该指标仅针对这些可控目标，不是独立自然问答准确率。样本中完整切片最多读取 8 个，容错预选最多 400 个，向量单批最多 512 行。Windows 查询内存每 2 ms 采样，可能漏过极短峰值，且包含进程基础开销；证据同时保留操作系统进程生命周期峰值，避免用采样值冒充硬上限。

| 切片数 | 关键词发布文件：原 → 新 | 进程首次查询：原 → 新 |
| ---: | --- | --- |
| 1,000 | 0.55 → 1.61 MiB | 928.57 → 854.39 ms |
| 10,000 | 5.88 → 17.73 MiB | 2463.34 → 1180.49 ms |
| 50,000 | 29.34 → 81.40 MiB | 16356.75 → 3932.93 ms |

首次查询未清除操作系统磁盘缓存，不能称为冷磁盘测试。新增容错倒排和定位元数据增加磁盘及首次构建工作量；build.milliseconds 包含合成资料、向量写入及双索引发布，不是公平的两版建索引速度对照。本轮没有给出建索引加速百分比。

## 尚未证明的能力

精确向量扫描和原件全量摘要仍随数据规模增长，常见关键词可能扫描大量倒排项，未宣称无界规模或最大并发。5 万切片已实测，百万级、真实高维模型、长文档/复杂表格分布、并发与长时间负载仍需单独测试。真实外部模型生成和重排延迟、独立 OCR/RAG 问答质量不由本轮固定向量诊断推定。密钥、上传、连接、会话和私人运行库未进入新增公开证据或交接材料。
