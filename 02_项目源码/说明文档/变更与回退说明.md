# 本轮变更与回退方法

本轮围绕用户确认的 16 张浅色 C 页面参考重做前端：统一导航与按钮，增加阅读/对照模式、独立来源页和来源地址恢复，调整资料、记录、设置、简报、上下文及工具入口，并保留原有证据、版本、只读和请求隔离约束。新界面使用真实数据组件，参考图不是生产界面的截图背景。

长答案使用安全 Markdown、GFM 与数学公式渲染；宽屏对照分隔线支持鼠标和键盘，小屏使用单栏。未发布、缺项、历史失效等状态仍需明确显示，不以视觉简化替代事实校验。新增依赖由 package-lock.json 固定，完整 dist 随包提供。

逐项功能映射、16 图对应关系、具体自动回归和浏览器检查以 `验收证据/` 的实际文件为准。本说明不声明所有模型能力已通过本轮真实问答。

## 使用前保存恢复点

将本 ZIP 原样留存；在新目录完整解压后使用。不要覆盖唯一的旧项目或旧 `.runtime`。首次启动在本目录创建新的运行环境，不自动迁移另一个项目的凭据与私人数据。

## 回退整个应用

1. 使用本目录启动器停止自己的实例，确认端口和目录一致。
2. 备份当前 `.runtime` 到仅自己可访问的位置。该目录可能包含密钥和原件，不要发到比赛包或公共仓库。
3. 从此前保留且确认可用的完整版本恢复到另一个目录，使用其对应源码、依赖锁和 dist。若要恢复旧数据，优先使用该旧版本的配套运行数据备份；没有兼容性依据时，不让旧代码直接覆盖新运行库。
4. 使用空闲端口执行预检并启动。确认可用后再切换使用，不同时让两个实例写同一 runtime。

## 仅恢复前端

仅在确认后端接口兼容且有明确旧前端快照时使用。应一起恢复该快照的 src、public、package.json、package-lock.json、构建配置及完整 dist；若需重建，先 npm ci，再 npm run build。不要只替换 CSS 或混用两版哈希资源。

本包不把旧快照再复制为第二套应用，也不提供未经验证的数据库降级脚本。开发过程的恢复快照保留在原工作区；如果只有本包，可重新解压本包恢复到本次交付状态。
