# 源码 ZIP 打包与完整性校验

在作品根目录使用 Python 3.12 以上运行 `package_handoff.py`。默认仅预检，不安装依赖、不调用模型、不创建运行目录、不执行 OCR，不生成外层报告或 RAR。

```sh
python3 package_handoff.py --check-only
python3 package_handoff.py --check-only --inventory ../源码包预检.json
python3 package_handoff.py --output ../03_作品原始文件.zip --inventory ../源码包实际核验.json
```

Windows 可将 `python3` 换为 `py -3.13`，或使用准备后的 `.venv\Scripts\python.exe`。输出必须在源码目录之外，文件必须尚不存在；需要再打包时另取明确的新文件名。脚本不会覆盖或删除旧包。构建或源码正在改动时不要同时打包。

包内只有一个根目录 `知衡作品/`。包括 Windows 四个 cmd、PowerShell 脚本、Mac 入口、完整后端/前端源码、已构建 dist、依赖锁、固定 E5 ONNX 与 tokenizer/许可、4 个业务或教学数据库及 schema、2 个性能数据库及 schema、12 份真实 PDF、18 份受控多格式样本、同源补充与可迁移复现输入。每次生成新的 `项目文件清单.json` 并逐项核对 ZIP 内摘要、字节数与 CRC。

默认排除虚拟环境、node_modules、私人 `.runtime*`、private/secrets/credentials、环境密钥文件、Git与编译缓存，以及维护用 AGENTS 和旧验收证据目录。遇到白名单下的其他凭据文件或符号链接会直接拒绝打包。外层最终报告、演示和 RAR 由交付流程单独组织；不再绑定旧日期或“待定稿”报告路径。

答案键保留在 `评测材料/` 下独立的 `离线评分/`，不会被迁移输入作为业务知识库导入。若知识库样本/samples 内出现答案键，打包预检会拒绝。45 场景输入与 21 个来源映射、44 项资产和模型清单摘要在打包前核对；不能拿这些文件检查冒充端到端问答或 Windows 实机验证。

在新目录解压后，进入 `知衡作品` 执行：

```sh
python3 校验项目.py
python3 scripts/prepare_inputs.py
```

两项均为只读、离线文件核验。新ZIP内清单对应打包时快照；维护源码里的旧清单不会被该脚本悄悄更新。需要使用或开发时遵循 README 和快速启动说明。
