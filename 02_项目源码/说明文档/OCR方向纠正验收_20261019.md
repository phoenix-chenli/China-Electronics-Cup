# Windows OCR 自动方向纠正验收（2026-10-19）

本轮只修复旋转方向与低质文字误用，不宣称复杂表格、公式结构或低分辨率数字已解决。解析版本为 `zhiheng-multimodal-3.4`。

## 行为

- 先识别原方向；文字质量不足时，最多比较0/90/180/270四个方向。高质量原方向不增加旋转调用，近似并列时优先保留原方向并标复核。
- 候选选择综合字符加权置信、可靠字符覆盖及足量长词的物理词框方向，不按字符数量或单一最高置信度选择。单字、纯数字或少数词不强行提供方向证据；评分不是准确率，也不能证明复杂公式正确。
- 方向尝试与原识别共用最多35秒预算，每个额外方向最多8秒；保留各次状态、耗时、质量指标和预算耗尽记录。单次失败允许尝试其他方向，取消向上传递，不发布取消后的部分结果。不依赖额外的OSD语言模型或远程API。
- 在纠正方向完成文字排序、表格定位和逐格复读后，将文字、表格与单元格框一次性逆映射回原图；文本偏移、表格行列保持纠正后的阅读顺序。原文件不改变，四分之一旋转交换非等向DPI的x/y。
- 所有方向都低质时返回空正文、空文字框、空表格和`unreadable`状态，避免乱码进入检索或图表证据。只改变状态而保留乱码正文是不够的。
- PDF导入、图片导入及按需图表OCR均使用统一适配器。按需OCR不覆盖原生正文与偏移，低质结果保留警告，方向审计可追踪。
- 检查点版本升级；已有导入结果需重新解析或重新导入，旧结果不会自动改写。

接口仍使用[Tesseract官方TSV模式](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)，方向判据属于本项目的候选诊断策略，不是官方准确性认证。

## 真实Windows复测

冻结材料为`评测材料/复杂文档专项/真实OCR`协议，2份公开原件的3个物理页、15个锚点、3种条件，共9张图片。Windows / Python 3.14.7，独立便携Tesseract 5.4.0.20240606，自带eng语言模型，OMP_THREAD_LIMIT=2。引擎仅在评测进程配置，未安装到系统或放入源码包。未调用外部生成模型。

| 条件 | 修复前锚点命中 | 修复后锚点命中 | 修复后3页耗时之和 |
|---|---:|---:|---:|
| 原始页面 | 15/15 | 15/15 | 4.932秒 |
| 逆时针90° | 0/15 | 14/15 | 13.157秒 |
| 50%降采样 | 10/15 | 10/15 | 3.042秒 |

三张90°输入均正确选中逆时针270°纠正；B11第84页仍漏一个数字锚点，未猜补。三条件合计由25/45提升至39/45；这是所选锚点命中，不是全文文字、数值或问答准确率。各组一次运行，耗时不是稳定性能基准，方向复读会带来额外耗时。

另对同3页生成180°和270°共6张派生图，方向选择6/6正确，锚点30/30（重复同15个锚点，不计新独立样本）。186个正文块偏移和367个定位框通过检查，原图及派生输入字节均未改变。主9图所有正文偏移及文字/表格/单元格框也通过检查。180°/270°是额外探查，不并入原冻结三条件分母。摘要、代码和结果哈希见同目录`OCR方向纠正实测_20261019.json`。
