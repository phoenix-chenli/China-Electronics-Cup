# 快速启动与环境说明

所有命令在解压后的作品根目录执行。包内含源代码、完整前端dist、固定E5模型、原件与数据；不含开发者凭据、私人runtime、Mac虚拟环境或node_modules。

## Windows 10/11 x64

1. 安装Python 3.13 x64（也可用3.12 x64）。32位Python不适用。首次依赖安装需要联网，不承诺空白电脑断网安装。
2. 双击 `首次准备.cmd`。它定位脚本所在目录，在 `.venv\Scripts\python.exe` 创建隔离环境，安装两份公共锁及 `backend/requirements.windows.lock.txt`，检查严格SQLite、原生模块导入和依赖冲突。
3. 双击 `启动知衡.cmd`，浏览器打开 `http://127.0.0.1:8876`；双击 `停止知衡.cmd` 结束本目录实例。终端可执行 `启动知衡.cmd --port 8877`，停止时用相同端口。
4. `环境检查.cmd`只读显示Python、依赖、OCR、模型配置是否存在及strict DQS状态，不发送连接测试。

入口支持中文和空格路径；建议解压到本机可写目录，勿直接在压缩软件中运行。脚本仅对当前PowerShell进程设置执行策略，不永久改变系统策略或PATH，不要求以管理员运行应用。系统强制策略阻止脚本时，可在根目录用 `py -3.13 start.py --prepare-only`、`py -3.13 start.py`、`py -3.13 start.py --stop` 执行等价入口。

普通运行不需要Node，包内dist可直接服务。只有显式 `--rebuild` 或dist缺失才需要Node/npm。解压改变时间戳不会自动触发构建。

## 原生依赖、DLL与OCR

ONNX Runtime使用CPU版，Windows需要相应Visual C++运行库；出现DLL加载错误时核对Python x64及 [Microsoft Visual C++ Redistributable x64](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170)，依据 [ONNX Runtime安装要求](https://onnxruntime.ai/docs/install/) 处理。不要以关闭检索、DQS或改用浮动依赖掩盖错误。

扫描件与图像OCR在Windows使用Tesseract。按 [Tesseract安装文档](https://tesseract-ocr.github.io/tessdoc/Installation.html) 获取可信安装程序，安装 `eng` 和 `chi_sim` 语言数据。`chi_tra`可用于繁体。中文入口会查找 `%ProgramFiles%\Tesseract-OCR` 和 `%LOCALAPPDATA%\Programs\Tesseract-OCR`，其他路径需在当前终端PATH中可找到 `tesseract.exe`。

```bat
tesseract --version
tesseract --list-langs
.venv\Scripts\python.exe start.py --check
```

语言包缺失会如实显示不可用。原生文字PDF、Office及数据库不依赖OCR才能读取；OCR输出为机器文字、坐标与置信信息，不保证表格关系恢复。Tesseract、语言数据及Visual C++安装包没有捆绑在作品ZIP内，须按各自许可取得。PyMuPDF的AGPL/商业许可和E5模型MIT许可边界保留在随包许可中，不把全部第三方组件改称项目自有。

## macOS

Python 3.12及以上并支持SQLite strict DQS；本轮Mac检查环境是Apple Silicon、Python3.13.6。原生OCR使用Vision，需Swift/Xcode命令行工具。可双击 `.command`，或运行：

```sh
python3 start.py --prepare-only
python3 start.py --check
python3 start.py
python3 start.py --stop
```

启动器使用真实跨平台文件锁，启动/停止核验健康信息、工作目录、命令行及进程创建时间。新实例通过仅本地的随机令牌请求优雅退出；等待超时后，只处理身份仍匹配的实例及事先确认的子进程。不会按端口或进程名批量结束进程。停止不删除资料，模型请求不会自动重发。

默认出站队列在单个服务进程内，按提供商origin与凭据摘要共享一个在途槽位，不按项目或角色另开并发。显式设置 `ZHIHENG_PROVIDER_PACING_DIR` 才启用跨进程协调：POSIX要求当前用户私有0700目录；Windows为新目录设置当前用户ACL，对既有目录只校验、不放宽权限。排队与冷却可取消，进程异常退出由操作系统释放锁，锁文件不能手动删除。

## 配置模型与首次使用

把 `说明文档/运行配置示例_无密钥.json` 复制为作品目录 `.runtime/model.json`，在本机填写自己的服务地址、密钥与实际可用模型ID。`table`用于问数，`document`用于文档和原页，`verify`用于复核。图像能力依赖实际服务。界面设置负责选择角色模型、保存和主动测试；首次地址与凭据仍由本机文件提供。macOS可设 `chmod 600 .runtime/model.json`，Windows将文件保存在本人账户可访问的本地目录，不共享给其他普通用户。

配置可读不等于已连通。连接测试和新问题会访问配置服务并可能计费；必要问题、Schema、检索片段及原页图可能出站，E5 embedding在本机执行。不要将配置或密钥加入源码、截图、报告或压缩包。包内不存在开发者连接，离线HTML可读历史结果，但不能离线生成新模型答案。

新建项目导入资料，或打开精选8份演示素材；导入不自动问答。最多12来源共同进入一次分析。对于受控复现，先看 [可迁移输入说明](../评测材料/可迁移复现/阅读说明.md)：它可建立真实新项目及source-id映射，不携带旧project-id或私有会话。
