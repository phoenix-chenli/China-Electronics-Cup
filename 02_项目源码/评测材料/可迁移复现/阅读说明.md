# 可迁移输入与独立复现

本目录从历史冻结计划另行导出45个场景，保留原问题、来源摘要、父轮及分组；内部冻结原件没有修改。相同ID在后续多轮计划中的定义采用后续明确版本，历史计划文件摘要仍在 `输入清单.json` 中登记。它是复现输入，不是新一轮测试结果。

原20题是8单表SQL、2多表SQL与10RAG。`sql-002`、`sql-003`额外补齐10个单表，2多表另作技术证据。所有45场景的真实历史答案和尝试见外层“实测与过程”及评审HTML；本目录不会把历史答案伪装成当前新实例会话。

## 在任意解压路径校验

在作品根目录运行（Windows将 `.venv/bin/python` 换为 `.venv\Scripts\python.exe`）：

```sh
.venv/bin/python scripts/prepare_inputs.py
```

该命令校验21个来源ID和44项数据、原件与模型资产的SHA-256，不安装依赖、不创建运行目录、不解析文档、不访问模型。输入路径相对作品根目录，不要求开发者用户名、绝对路径或原project-id。

## 创建真实的新项目与来源映射

首次准备完成后，在尚未启动的干净解压目录运行：

```sh
.venv/bin/python scripts/prepare_inputs.py --prepare --sources chinook,definitions
```

它通过应用实际项目创建与导入接口创建 `.runtime`，将新project-id和source-id写入 `.runtime/可迁移来源映射.json`。默认只导入教学库和合成口径文本，执行小文件真实解析，不调用模型。目标目录已有任何内容时拒绝覆盖。需要保留现有工作时，可用 `--runtime 新目录` 单独准备；此时它不是默认启动器的运行目录，不能混称已接入原项目。

更多来源ID见输入清单。PDF和图像只排队，不在准备脚本中OCR；普通服务启动后可能处理其导入队列，选择这类来源意味着需要等待本机解析。包中没有整套私有解析缓存，也没有声称所有2965页已在Windows预解析。快速查看全部历史结果应使用外层离线HTML，不必重新导入长文档。

新问答前由使用者配置自己的模型连接，再在UI中选择新来源提问。多轮按 `parent_case_id` 依次承接实际新answer-id，不能沿用历史ID。动态下一问用例保留原规则与历史实际问句：新复现必须从新父轮的真实建议中选择，不能发送占位文字或把历史建议说成新生成。此脚本没有自动付费复测入口。

## 输入与答案隔离

`离线评分/`只供独立人工核对，保留四份答案键的事实及历史摘要。准备脚本完全不读取这个子目录，也不把题目、答案或历史评审记录导入业务知识库。新结果必须独立保存、核对，不能改写历史45场景记录。

`boundary.sqlite`对应随包“边界测试数据库.sqlite”；初赛输入Chinook与知识库Chinook为同一摘要，不是新增数据库。映射见 `数据与模型清单.json`。受控合成口径单独保留，不并入12份真实文档。

## 两规模性能输入

`受控输入/性能尺度/`保留1000行和10000行两个SQLite。schema见根目录 `schemas/性能受控记录_1000_建表结构.sql` 和10000行对应文件。生成式为：`i=1..n`；`region=区域{i%20:02d}`；`status=已完成 if i%4 else 取消`；`amount_cents=(i*37)%100000-5000`，`id=i`。字段单位为分，数据库包含 `(region,status)` 复合索引。

生成和本地只读执行方法原样保留在 `evaluation/acceptance_offline.py` 的 `sql_scale`。`历史两规模SQL性能.json`只将历史路径映射到包内，保留2026年10月18日的实际测量环境、样本、首次调用与后5次中位数，不是Windows耗时或模型端到端时延。重新测量请输出到新的目录，并明确新环境；不要覆盖本文件。
