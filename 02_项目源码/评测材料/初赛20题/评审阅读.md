# 固定20题的阅读与复现

本目录提供10道SQL和10道文本RAG题，问题、7份原件和离线参考答案保持原冻结字节。它是事先按能力覆盖选定的开发集，原题集名称为 `paired20-common-capability-v1`，不是隐藏测试集或官方评分软件。

供评委直接阅读的逐题说明位于初赛提交目录《测试用例与评分说明》，内容包括问题、完整预期行集、原文定位及判定要点。S01至S10、R01至R10为阅读编号；真实运行使用suite内原ID及交替顺序。所有本轮实际结果留为待实测。

## 如何人工核对

1. 阅读题目与预期结果。SQL题只使用chinook.sqlite，RAG题只使用该题source_ids指定的文档。
2. 查询数据库或打开原文核对参考答案。PDF按物理页；DOCX按章节和非空段落；TXT、Markdown按原文件行号。不将旧解析索引当作纸面页码。
3. API恢复后，在独立测试项目逐题原样提问，各题新建分析；保存实际回答、查询、引用、工具轨迹与耗时。
4. 参考答案只用于离线评分。不要导入“离线评分”目录或本说明至业务知识库，也不要发送给答题模型。

## 不调用API的材料校验

进入包含start.py的项目根目录，执行：

```sh
python3 评测材料/初赛20题/校验用例.py
```

该命令使用Python标准库和项目内的纯离线比较函数，校验7份原件的SHA-256、输入与答案对应关系，并只读执行10条参考SQL。它不启动问答服务、不读取模型配置、不发出网络请求。“通过”表示参考材料一致，不是20道模型题通过。

## API恢复后的真实运行

先按项目README安装依赖并准备有效连接。以下命令用于生成新的运行记录，会真实调用模型。历史选定结果已留档，新运行独立保存。使用一个全新的输出目录，并把`<有效配置目录>`替换为存放现有model.json的本机目录，不要把密钥写在命令或提交材料里。以下示例在项目根目录运行；Python需使用已安装项目依赖的环境（macOS/Linux通常为`.venv/bin/python`，Windows为`.venv\Scripts\python.exe`）。

```sh
python -m evaluation.runner run \
  --suite 评测材料/初赛20题/输入/suite.json \
  --runtime /absolute/path/first20-runtime \
  --output /absolute/path/first20-run.json \
  --mode live --config-runtime "<有效配置目录>" --timeout 1800
```

`runtime`与结果文件都必须尚不存在，结果文件放在runtime之外；它们不能位于配置目录中。1800秒是单题墙钟取消边界，不是API次数上限。首次与复测各用独立编号，不能覆盖失败记录；未知POST结果不自动重发。命令中的路径为填写示例，不是已有实测文件。

## 独立复核与离线评分

逐条对照真实回答和原件，给出事实正确、内容完整、引用有依据三个判断。SQL还必须有真实执行轨迹、正确行集及业务口径。审阅结果须绑定运行文件的SHA-256和该条record的`evaluation.core.record_digest`；审阅者及人工/自动方式如实注明。不能用模型自报支持来代替核验。

```json
{
  "run_sha256": "实际first20-run.json的SHA256",
  "reviewer": "实际复核人或实际复核方式",
  "cases": {
    "sql-001": {
      "record_sha256": "实际该条record的摘要",
      "correct": true,
      "complete": true,
      "grounded": true,
      "notes": "填写对照原件和查询轨迹的具体依据"
    }
  }
}
```

上面只说明格式，不是已完成的审阅；每条结论须按实际记录填写。没有复核时暂不提供`--reviews`，需要审阅的题保持pending，不能称通过。

```sh
python -m evaluation.runner score \
  --input /absolute/path/first20-run.json \
  --key 评测材料/初赛20题/离线评分/参考答案.json \
  --reviews /absolute/path/first20-review.json \
  --output /absolute/path/first20-score.json
```

评分保留10、10、20的固定分母，包括API错误、失败与未运行项。SQL结果匹配不能替代事实、完整性及依据审核；RAG按语义和原文判定，允许同义表达。当前参考键内的`status=completed`描述预期终态，不代表系统已完成该题。

## 材料与适用范围

- 输入/suite.json及同名.sha256：固定问题、来源白名单、冻结摘要。
- 输入下7份原件：Chinook公开教学库，6份预先编写的合成文本资料；来源与许可随suite保留。
- 离线评分/参考答案.json：原参考SQL、全部期望行、RAG事实要求，保持原字节。
- 选题说明.json：事先选题理由、原ID及来源题库摘要。
- 结果记录模板.csv：20题待实测记录，不含伪造结果。
- 参考材料核查.json：本轮离线参考SQL及原文核查，不是模型答题结果。

这20题不覆盖图像、扫描OCR、复杂表格、公式、跨源推理、澄清及连续多轮。它们的专项结果需另行验证，不能并入本套基础题分母。
