# 终版回答记录与评测契约

当前为终版开发中的增量约定。旧 API 字段继续保留；这是功能契约，不是模型正确率报告。

## 回答与来源

新记录使用 `schema_version: zhiheng.answer.v6`。`source_revisions` 保存所选来源的原件 SHA、解析版本和内容修订，与 `sources` 一起冻结；`context_revision` 在结构化上下文接入前明确为空。`suggestions` 初始为空、`suggestion_state=hidden`，不能将预留字段解释成建议功能已完成。

结果使用 `zhiheng.answer-result.v1`，保留原始 claims/evidence/SQL/calculations，同时新增：

- `result_tables`：仅将完成态实际主结果表投影供显示。失败执行的 `query.executed_result` 仍为未采纳审计，不进入结果图表。
- `coverage`：复制已存在的 completeness；旧记录缺失则 `not_recorded/complete:null`，不补造覆盖通过。
- `evidence_graph`：原件、证据、计算、事实和回答间的实际 ID 关系。无法对应的引用列在 unresolved，不能绘制为已验证的边。原件转换关系按实际 source_groups 保留，不根据文件数量推断独立来源数。
- 定位精度按保存事实区分 page、text_span、table、table_rows、query_scope、unspecified；整页图像即使存在模型候选框，也仍为 page。

读取旧记录只做深拷贝投影，标记 `zhiheng.answer.legacy` 和 `projection_only`；旧状态、来源、记录正文不回写。JSON 导出继续保留原保存结构及其 body 摘要，不能拿投影后的内容冒充原记录字节。

## 可观察事件

`answer_events` 与回答状态在同一 SQLite 事务中提交，包含实际阶段、状态、时刻、累计耗时、距上一事件时间和结束时输出数量摘要。它不包含模型隐藏思维、提示词、连接凭据或推测的未来进度。

`GET /api/projects/{project_id}/answers/{answer_id}/events?after=0&limit=100` 返回 `{items,next_after,has_more}`。after 为已见序号，limit 1—200；项目隔离、序号递增。取消与终态不可由迟到结果覆盖，服务重启将中断任务记 failed 并追加 interrupted 事件；不自动重发可能已计费的 POST。回答 JSON 投影默认带前 200 个事件，完整历史使用分页。导出在同一只读数据库快照中附带 execution_events，保留新旧记录差异。

## 评测输入与判定

`python -m evaluation.runner --help` 提供真实运行、故障注入、离线重放和离线评分。输入集合 `zhiheng.eval-input.v1` 仅允许问题、来源、范围、划分、父轮和标签，不接受参考答案。单独评分文件通过输入 SHA 绑定；模型输入采用严格白名单。原件和输入都需 SHA 校验，同源簇不能跨开发/保留评估划分。

每次试验用新报告和新隔离运行目录。记录代码摘要、资料摘要、模型 requested/reported、实际使用量、全部终态/失败、耗时；代码运行中变化明确标记，不能作为冻结最终评测。真实运行读取指定本机模型配置，不复制到源码或报告。

SQL 结果按多重集比较；有排序要求时按顺序比较，保留重复次数、NULL、精确数字类型、指定容差。执行成功不代表文本正确；自由文本必须有绑定该记录摘要的正确性、完整性、依据评判，否则记 review_pending。记录评判者身份，AI 评审不冒充真人研究。故障注入、回放、未运行、待评判都分别标记，未运行和待评判不从端到端分母中删除。
