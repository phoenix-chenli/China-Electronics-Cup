# 知衡演示视频：操作、提问与逐句讲解

建议成片约7分50秒，16:9，主体是实际软件操作。现场新问答与历史记录回放分别标注。下面的时长是录制建议，不是官方视频时限。

本脚本依据2026年10月19日最终前端、已保存的7轮实机记录、正式评审HTML与六轮父链编写。问题与核对值来自现有证据；新一轮的回答措辞、耗时和状态可能不同，应以实际运行画面为准。

## 录制前准备（不放进成片）

1. 在本机双击同目录的 `启动录屏工作台.command`，等待终端显示服务已启动，然后打开 `http://127.0.0.1:8905`。选择项目“真实复杂业务资料库”。本入口已做只读检查：3份主要资料、5个关键历史回答及模型配置文件均存在；未替你启动或发送问答，配置存在也不等于当前模型服务已连通。
2. 同时在另一个浏览器标签页打开 `01_初赛提交/00_评审导读.html`，供长链与历史回放使用。它离线只读，不生成新答案。
3. 录屏入口复用本机 `.runtime-complex-corpus` 中已有资料和历史。普通 `start.py` 使用的 `.runtime` 当前是空项目；不要录到空白工作区后误以为历史丢失。该录屏入口只适用于当前Mac，不加入提交RAR、不复制密钥、不处理排队导入。新问答使用正常模型网关，由你点击发送后触发，并保存为新记录；不能把它们并入此前7轮/50请求统计。
4. 预先找到三个来源：`chinook.sqlite`、`boundary.sqlite`、`B08_EPA_市政营养盐去除技术参考_2008.pdf`。切换场景前点“新分析”，重新确认资料范围。不要把上一段的数据库和PDF一起勾着。
5. 用“记录”提前找好 `Central Johnston` 的回答，以及跨源超时回答。长文档有历史 `attention` 解析质量状态，不要把它改成“全部解析完美”；本例使用的是已经核对的原页与表格。避免现场重导入449页PDF。
6. 浏览器缩放100%，字体可读，录制浏览器窗口；只保留工作台和评审导读两个标签页。关闭通知，隐藏书签及其他个人页面，开始录屏前收起终端。麦克风先试录10秒，确认讲解和画面同步。
7. 录制前完整看一遍下文。正式录制时SQL一次、澄清两轮即可，不要为追求漂亮答案连续重发；耗时较长时保留真实首尾并标“等待片段加速/省略”。若本次没有完成，讲解也要跟随真实状态。
8. 录完回到启动脚本的终端，按 `Ctrl+C` 停止本轮录屏服务。不要按端口强杀其他服务，也不用删除任何runtime。

如果系统不允许双击，可在终端执行：

```sh
python3 start.py --port 8905
```

## 可替换的多表SQL亮点（增加约30–40秒）

如果需要突出中级能力，可在SQL段后使用评审HTML“三个完整案例”→“多表SQL · 聚合粒度”，回放以下问题：

```text
只看至少卖出过一首曲目的艺术家，他们名下总曲目数超过50的有哪些？输出艺术家编号、名字、总曲目数。总曲目数包括未售出的曲目。
```
