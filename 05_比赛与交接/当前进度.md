# 当前进度 · 2026-10-09

版本 0.6.0 已接入 RAG 主问答。本轮在上述基础上补齐 DOCX 解析、数值反证与 OCR 接入骨架，并首次完成 Windows 实机启动与业务路径验证：280 项独立 Python 隔离回归（17 个模块）、TypeScript 与正式网页构建通过。最终记录见“03_测试验收/验收证据/Windows实机与DOCX验收.json”和“RAG验收.json”，以及本页下方各节。旧版智能体和通用问数验收保留为历史记录，未重复累计。

## 数值反证 · 2026-10-09

- 新增 backend/counter_check.py：汇总值由一条 SQL 表达式产生，发布前再用贡献明细在 Python 中以 Decimal 独立复算，属于不同引擎、不同舍入的第二条路径。
- 覆盖四类独立校验：单值汇总用明细求和并核对订单去重数；分组排名用守恒检查（各组金额合计 = 明细合计）；计数指标用明细去重；增长率按两个对比期分别求和。
- 不一致时明确标注“已阻止发布该结论”，结论状态记为 needs_evidence 并附缺口说明，覆盖率同步下降，不会把未经复算的数字当作确定结论。
- 明细超过读取上限、缺少金额字段或没有贡献明细时记为 unverified，不伪称通过。
- 结论携带 counter_check 字段，/api/evidence/verify 在既有三项检查后追加“数值反证”一项；分析页结论下方显示复算徽标，悬停可看说明。
- 独立复算只证明算术一致，不证明业务口径正确；该边界写入检查说明。

## OCR 接入骨架 · 2026-10-09

扫描件识别需要已审定的模型权重，本仓库不含也无法自行下载核验，因此本轮交付**接入骨架**而非声称已实现识别。

- 新增 backend/ocr.py：识别只在模型包内**每个文件都与清单 SHA-256 一致**时执行；模块不联网、不下载，也从不伪造摘要。
- 清单由操作者提供（06_运行环境/OCR模型包.manifest.json），必须声明适配器、许可证、模型包 SHA-256 与逐文件摘要；缺角色、非法文件名、非法摘要都会被拒绝并给出具体原因。
- 安装流程先校验模型包摘要，再解压并逐个复核成员摘要，任一不符即停止且不落盘；安装记录写入模型目录的 .complete。
- 新增 GET /api/ocr/status、POST /api/ocr/install、POST /api/ocr/uninstall；/api/health 与 /api/settings 返回真实能力状态与原因，不再固定写死“未启用”。
- 识别结果写入版本固定的解析版本：字符偏移精确，位置按**行级**给出并在 quality 中标注 box_precision=line，不把行坐标当作逐字坐标；低置信行触发“识别结果待复核”并使文档进入 needs_review。
- 未安装时扫描页与图片保持原有的“需要文字识别”与空文字状态；重读接口也不会把重新读取文字层冒充识别。
- 已实现并测试的确定性部分：dbnet_ctc 适配器的连通域框选（行程编码两遍标记）、CTC 贪婪解码、置信度与低置信统计、清单与摘要校验、能力状态、以及解析/索引/定位/重读的整条接线（用 fixture 适配器验证）。
- **未验证**：真实权重下的识别准确率、旋转与模糊页面、跨页表。待提供已审定模型包后即可打通识别并补实测。

## DOCX 解析 · 2026-10-09

- 新增 backend/docx_reader.py，仅用标准库读取 OPC 包内 word/document.xml，不引入 python-docx、lxml 等新二进制依赖或新许可证义务。
- 标题层级只取自文件声明的 w:outlineLvl 或标题样式名，不从字号或位置推断；表格按行转为管道文本并保留表头分隔行，段落、表格与文本偏移保持一致。
- Word 不保存固定分页，因此 DOCX 按一个逻辑页处理并报告段落顺序，不伪造页码；定位精度为 text_range，可像 Markdown 一样做原文范围定位、搜索、局部重读与版本固定。
- “需要文字识别”只在包内确实存在 word/media/ 图片且正文无文字时标记，不再把所有空正文都当成扫描件。
- 接入导入白名单、示例复制、前端导入接受格式、来源筛选与格式标签；新增合成样本“衡岭设备保修办法.docx”（7 个标题、1 张表、470 字，含公开合成标记）。
- 示例知识库现为 27 份：25 Markdown＋1 DOCX＋1 PNG，满足官方“不少于 10 份”的数量要求。

DOCX 已用本机封装运行时实测：索引状态 ready、定位精度 text_range、原文定位与局部重读通过，并已进入 RAG 切片（2 块）与 FTS5 BM25 检索；向量步骤因本机未安装审定模型包而明确失败，未伪称就绪。表格、PDF 与扫描件样本仍需补充。

## RAG 本轮完成（2026-10-06）

- 固定原件 SHA 与解析版本的结构切片，384 词元预算、48 词元重叠；本地 tokenizer 不可用时明确标记保守字符计数，避免伪称模型分词。保留标题、表头、单位、原文范围及旧解析。
- jieba 0.42.1 分词与真实 FTS5 BM25、512 维 BGE 向量、RRF（k=60）、BGE 重排，最多 8 份完整原文片段。关键词统计按不可变发布代次固定，模型及向量代次改变会停止使用或明确降级。
- 主模型规划所需事实，检查证据充分性，生成原子结论，再核对每条引用与最终答全情况；不支持的结论不发布。仅独立可回答子问允许部分支持。数值改写和文档计算保留精确原文及单位检查。
- 全库、全文、页面、选区范围与历史版本继承；服务端保存来源，不接受客户端自造索引清单。归档阻止新检索，历史原文仍保留。范围冻结在任务写事务之外，避免解析嵌套写锁。
- 本地 CPU ONNX q8 真实执行，主动离线安装公开模型；检索与重排连接单独测试、启用和固定版本。外部批量索引采用十分钟、一次使用的文档预览，后台每批发送前后重新检查资料及连接。
- 8 个工具调用、12 次模型调用、180 秒总预算和共享取消；检索子阶段实时记录真实起止、失败和耗时。超出总预算停止，单个检索模型故障可明确降级。拒答及部分支持的伙伴显示待补充状态。
- 20 份公开合成制度文档、160 个冻结评估问题及评估入口，覆盖跨文档、同义、日期、条件、数值、冲突、无答案和部分支持；清单验证通过，真实生成质量待评。
- Windows 依赖共 52 项，保留原 35 项版本。新增官方 wheel 核对 PyPI SHA256 与 RECORD；jieba 为核对官方 sdist 后本地构建，未冒称官方 wheel。公开模型包仅有审定权重、配置、分词器与 MIT 许可。
