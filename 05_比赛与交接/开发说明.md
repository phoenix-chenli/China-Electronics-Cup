## TokenDance 连接与稳定性

使用原生兼容聊天接口 `https://tokendance.space/gateway/v1/chat/completions`，不经过 Codex 适配器。当前连接每次请求 120 秒，总轮次 600 秒；4 个网络工作位，排队也计入请求预算。规划与证据评审使用 JSON 输出。TokenDance 的 DeepSeek 请求使用 `max_tokens` 与 `thinking:{type:"disabled"}`，文本连接探针同样关闭思考；原 Qwen3.8 的 JSON 调用继续使用 `enable_thinking:false`。参数依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/) 并以 TokenDance 实际探针核验。输出预算截断、空回答与无效评审 JSON 均属于技术失败，不混同为资料不足；已保留的来源仍可查看。显式工具名放入 action 或 arguments 的两种无歧义格式会被规范化；冲突、未知工具、来源范围和只读 SQL 校验继续执行。已知但本轮不可用的工具只返回范围错误供模型修正，不执行，也不改变资料来源。

仅在连接建立失败、请求体尚未发送时自动重连一次。读取中断、HTTP 错误或限流不重复发送付费请求；页面给出错误与手动重试入口。页面查询任务在服务端运行，刷新可恢复，短暂读取失败继续轮询；取消及时结束本机等待，但上游已收到的请求可能仍在处理。重启保存配置和历史，进行中的任务标为中断并提供重试，不虚构续算或成功。网络与上游可用性无法保证永久不中断。

凭据只存在本机运行数据的加密连接记录，解密主密钥由本机权限保护；公开 API、Git 和交接包不包含密钥。分发后的新机器需自行填写连接。浏览器不持有 TokenDance 凭据。

## 正式解析入口

backend/document_native.py 读取安全 OOXML、PDF 表格与几何、实际线框网格，保存来源 ID 和连续文字范围；document_providers.py 执行固定 RapidOCR、模型安装与视觉结构核对；document_tasks.py 管理冻结预览、持久任务、取消 / 中断 / 重试、不可变发布；documents.py 管理当前解析指针与历史定位。frontend/src/document-processing.tsx 与 css 提供设置、预览、任务和结构展示；evidence.tsx 展示原文与图内高亮。

接口前缀 `/api/document-processing`：GET/PUT `/config`，GET `/models`，POST `/models/install`，POST `/preview`，POST/GET `/tasks`，GET `/tasks/{id}`，POST `/tasks/{id}/cancel`、`/retry`。解析请求含 document_id、version、parse_id、pages、mode(native/ocr/vision)、rotation、connection_id，可选 media_ids；视觉提交必须包含有效 preview_id 与 accepted=true。DOCX pages 表示逻辑节，默认处理选中节的全部嵌图。

预览冻结原件 / 基础解析 / 连接 / 模型及隐私版本，十分钟有效、一次使用；视觉调用发送预览中同一图片字节，记录 SHA 与实际字节数（不含 base64 传输膨胀）。取消或保护条件变化后不能发布部分结果。最多 40 张图片、2 工作者、12 个排队位置、900 秒总预算；OCR 单次 120 秒、视觉单次 60 秒。

解析状态 confirmed 表示提取条件与来源绑定通过，不表示人工审查。低于 0.8 的 OCR 行、视觉无独立依据或估读结构、未核实图表数字关联标为 pending，从引用与 RAG 中排除。OCR 保留真实行框，禁止插值制造字符框；DOCX 使用 media_id 与图内坐标。新解析原子切换 ef_document_active_parses；旧解析用于历史引用，新索引必须匹配当前解析。

## 模型主问答开发

`POST /api/query`、`POST /api/query/recompute` 及会话任务统一走 `agent.execute`。`GET/PUT /api/agent/config` 参数为 `{mode: local|auto|model, connection_id: null|id, query_scope: sales|database|knowledge|hybrid, database_connection_id: null|id, max_steps: 8}`。GET 返回可用模型及数据库的公开选项，不包含主机、路径、用户或密钥。数据库 ID 为 null 时读取本机业务库及已导入表；其他 ID 对应已测试、启用且符合隐私设置的 SQLite / PostgreSQL / MySQL 连接。

旧配置默认 `local + sales`。销售范围的 auto 未配置模型时可用本地查询；数据库范围必须有可用模型，不接受 local，也不会在模型失败后切回销售示例。多个可用模型需明确选择，指定连接失效或调用失败时明确报错。每次调用重新检查隐私、启用 / 测试状态及连接版本。数据库追问继承服务端历史结果的来源和已记录的版本，排队任务冻结提交时来源上下文，修改全局设置不会把原会话悄悄转到另一库；同一连接版本变更也需新建问答重新确认。

模型使用现有 OpenAI 兼容聊天连接，不新增 SDK。严格 JSON 动作为 `tool`、`answer` 或 `clarify`，可附带 plan。原有 `schema.inspect`、`business.query`、`document.search`、`formula.calculate`、`evidence.verify` 保留，新增 `database.schema` 和 `database.query`。只有 database.query 接受受保护的 SQL；其他工具继续拒绝 SQL / 代码。数据库范围禁止调用销售业务查询，避免所选数据源与实际答案不一致。文档工具返回有限原文、版本、页码与来源 ID；公式参数必须匹配本轮数值、单位及来源，计算使用安全表达式与 Decimal，业务系数不能作为无来源常数。

答案选择工具返回的 `fact_id`，或使用 `evidence_id` 加精确 `quote`。服务器校验数字 / 单位未被改写、原文可定位，允许一次答案修正。数据事实带 query_id，最终数据结论只取同一次查询，恢复对应 query_spec、SQL、返回行及公式快照；需要跨表统计时在一条 JOIN / CTE / 子查询 SQL 内完成。模型计算继承参数的查询作用域及模拟属性，不自动推断量纲。服务端核验是约束、来源与事实绑定检查，不应展示为模型准确率。

预算固定为 8 次工具、12 次模型、600 秒；单次工具上下文最多 26,000 字符，累计消息最多 60,000 字符。只发送当前问题、有限结构化上下文和相关证据，不能加入完整会话、文件路径、凭据或全库样本。进行中耗时未知时留空，结束后填写实测耗时；返回内容为有限真实快照，不能虚构完成步骤。

`ef_task_traces` 独立表记录任务的 events/agent 快照，兼容原任务表。任务成功、失败、取消及启动恢复在事务中收口；重启时未知耗时/结束时间留空，保留 recovered_at。连接网络调用使用有界执行池；用户取消可及时退出等待，已发出的服务端请求可能仍在超时内结束，不能声称远程算力也已终止。

智能体隔离回归：在上述测试入口后追加 `--module tests.test_agent`；任务恢复追加 `--module tests.test_conversations`。模拟模型使用本机 HTTP 服务，验证真实协议、调用/失败/耗时、取消和约束，不依赖外部密钥。实际文本服务验收仍需补模型版本、参数、端到端耗时及独立人工核对。

## 通用数据库问数开发

`database_query.inspect(connection_id, table_names, cancelled)` 返回公开来源、SQL 方言、表字段、主键、唯一键、外键、候选关系及表清单。50 张以上表需显式 table_names 选择；关系候选数量与操作时间受预算限制。`guard_schema(snapshot)` 只提供实际可用的表字段及已验证关系。候选关系先验证目标键唯一及子表非空键覆盖，空样本或未通过验证的关系不进入 SQL 授权图；检查证明数据关系可用，不能确定其业务含义。

`sql_guard.validate(sql, schema, dialect=..., max_rows=..., max_nodes=...)` 用 sqlglot AST 解析和限定字段作用域，允许受保护 SELECT / WITH、聚合、JOIN、非递归 CTE 和子查询。JOIN、相关子查询和直接键比较子查询需使用完整可信关联键；CTE 中键只允许沿直接投影追溯。禁止写入、系统指令 / 表、未知函数、外部表函数、笛卡尔积、自然关联、递归及过深复杂结构。模型使用 `?` 位置参数和列表，服务端安全转换 PostgreSQL / MySQL 驱动参数，不能拼接值到 SQL。通过记录只表示这些检查通过。

`database_query.execute` 在执行前重新读取结构及验证关系，检查来源连接 revision 与结构 fingerprint。SQLite 使用只读 URI、query_only、trusted_schema 及 authorizer；PostgreSQL 使用只读事务 / statement timeout，MySQL 使用只读事务 / max_execution_time 及驱动超时。每次数据库操作最多等待 5 秒，使用有界执行池并响应取消。查询最多返回 200 行，第 201 行仅用于截断判断；结果总大小限制为 2 MiB。截断数据不代表全表，不能在客户端把这 200 行当作全库汇总。

每轮最多 3 次 database.query 尝试，包含初次及失败；仍受总工具 / 模型 / 时间预算限制。模型收到具体失败可修 SQL，但不会获得追加表权限或取消只读保护。超过模型上下文预算的结构需要缩小 table_names 后重读。

导入的键和关系保存在 `ef_database_import_metadata`；导入与元数据通过受控连接一并提交，数据库问数仍只读业务库。SQLite 文件导入保留原表键元数据；外部选表导入映射本批实际表名，对未导入父表的关系只保留待解析元信息，不直接授权 JOIN。导入关系之后仍会实测唯一性与覆盖，不将元数据记录当作已生效数据库约束。

通用结果标识为 `query_spec.metric='database'`，`result.database_query` 包含 source、sql、params、joins、validation、attempts、row_limit、truncated、columns、rows、explanation、query_id。SQL 来源 locator 保存 query_scope、实际 SQL / 参数 / 列 / 行、来源、结构版本及 result_sha256。fingerprint_scope 为 schema_snapshot，不能用它表示整个业务数据库内容版本。前端按原字段和实际数值渲染，数据库结果不生成销售条件、单位、奖金情景或区域 / 年份快捷重算；通过自然语言追问修改条件。

新增隔离模块为 `tests.test_database_agent`、`tests.test_database_query`、`tests.test_sql_guard`，可使用测试入口的 `--module` 逐个运行。模型集成使用本机 HTTP 模拟服务；外部驱动协议夹具和模拟模型只证明协议、保护及链路。真实 PostgreSQL / MySQL、自然语言业务准确率和多库泛化需另用实际服务及未参与开发的冻结数据验收。

架构参考 [ERP-AGENT-open-source](https://github.com/wodrake/ERP-AGENT-open-source) 的规划、工具执行及核验思路，本轮代码基于本项目现有工具独立实现，未引入其运行依赖。
