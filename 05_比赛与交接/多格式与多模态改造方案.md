# 多格式解析与多模态理解改造方案

版本基线：EvidenceFlow 0.6.0；调研与设计日期：2026-10-08。目标版本：0.7.0。

## 目标与已有缺口

本轮补齐 DOCX、扫描 PDF 和图片 OCR、复杂表格与图表的结构化理解，并形成“准备任务 → 真实识别 → 校验 → 保存新解析 → 建立 RAG 索引 → 原件定位”的闭环。交付源码、Windows 便携 RAR、仓库提交与 Release，完成后暂停。

当前 store.extract 只提取 PDF 原文字及文本文件；导入白名单缺少 DOCX。documents 的重读只是再次提取原生文字。extensions 的单页视觉回复保存为临时补充，不进入正式解析和检索。不得把这些既有行为宣称为 OCR 或正式视觉解析。

## 总体路线

1. 原生优先：DOCX 读取 OOXML；PDF 保留原文字和坐标，读取矢量/文字表格；DOCX 原生图表读取保存的数据缓存。
2. 扫描与图片：主动安装固定 OCR 模型后执行本机真实 ONNX 推理。识别结果保留文字、四点框、识别分数、输入图像摘要、模型及耗时。
3. 困难结构：使用已测试启用的视觉连接，以严格 JSON 提取表格网格、图表轴/图例/系列/数据点和区域；单页临时补充继续保留，不能自动升级为正式事实。
4. 校验与发布：结构合法、数字与可观察文字相符、来源区域有效后保存；失败和疑难内容保留状态。整批任务不得在取消或版本变更后激活新解析。
5. RAG 使用正式新解析，历史问答继续绑定旧 parse_id。回答区区分原生文字、OCR、结构化视觉提取和人工确认状态。

## DOCX 原生解析

采用受限 ZIP + OOXML 读取，避免额外引入 Office、LibreOffice、Docker 或 Word COM。限制条目数、展开字节、XML 大小和嵌套深度，拒绝 DTD/外部实体、路径穿越及外部关系读取；不执行宏或嵌入对象。

按 body 的段落、表格顺序读取，解析标题样式、列表、段落、换行、超链接可见文字、脚注/页眉页脚的来源身份。分成逻辑节；明确不是原 Word 分页。图片保留关系、媒体摘要与原包内部路径，不把图片占位文字写入可回答证据。

表格保存唯一物理单元格、行列起点、rowspan/colspan、表头角色、空白与段落来源；纵向 continuation 引用起始格，避免合并值被重复计算。遇到不合法合并关系时标疑难。嵌套表保存父格关联。

图表读取 OOXML 中确实存在的标题、系列、分类、数值缓存与轴单位等信息；缺失缓存或不支持的绘图类型明确待视觉解析。保留 chart part 路径与数据点身份；不用形状高度补造数值。

## PDF、图片与 OCR

PDF 每页保留已有字符级坐标、旋转变换及书签。原生表格调用 find_tables，保存原始网格和单元格 bbox。没有足够文字的页面及图片可选择真实 OCR；混合页允许明确重识别，不把原生/OCR 重叠内容无条件相加。

候选运行器采用 rapidocr 3.9.0 与已有 onnxruntime CPU；固定中文 mobile 模型、字典及摘要，最终模型文件以实际安装和识别验证为准。rapidocr-onnxruntime 1.4.4 的官方元数据要求 Python <3.13，不用于当前 Python 3.13 环境。依赖、wheel SHA/RECORD、模型来源及许可证随交付登记。

模型安装必须由用户主动执行；导入文件不触发联网下载。运行只使用固定本地路径，缺模型明确失败。OCR 分数不是正确率。低分关键文字、空白、旋转失败、漏字与单位不清均显示待复核；不能用固定句子冒充 OCR。

识别行只有行级框时定位精度标为行或区域，不均匀拆分成伪字符坐标。可选择 0/90/180/270 度输入旋转，记录变换；行方向分类不等于完整自动整页方向纠正。

## 表格与跨页关系

正式结构包括 table/segment ID、页/逻辑节、bbox、单元格 ID、原文、行列范围、表头祖先、单位/脚注、方法及疑难状态。Markdown 是派生阅读视图，结构 JSON 才是保存依据。

原生 PDF 优先网格提取；扫描表采用 OCR 观测与几何/视觉结构匹配。校验越界、非法跨度、格重叠、表头引用、数字/符号/单位和列归属。合计用于报告异常，不能反推修改原数值。

跨页仍保存独立 segment；只有相邻页、列结构一致且表头/标题/续表/单位等依据相符时建立 continuation。保留连接理由和各段来源，不把上一页表头伪装成本页原文。无法确定的续表关系待确认，不自动合并统计。

## 图表结构与可信范围

保存类型、标题/说明、区域、轴标签/单位/刻度、线性或对数、图例/颜色/系列归属以及数据点的类别、时间、值和原标注。数字来源分为原生 chart 缓存、印刷标签和像素估读；精确问数只使用确实存在的原生值或可观察标签。

视觉响应必须使用固定 JSON，不可读项填 null。保留模型原始结果、模型及连接版本、输入图片摘要、裁剪范围、实际用量和耗时。不得把模型自报 confidence 当确定性校验。

对关键数字、表格单元格文字以及图表标签，与同区域的原生/OCR 观测进行独立核对；没有观察依据、存在冲突或只有估读的内容标待复核，默认不进入确定性数值证据。视觉结构校验通过仍不等于人工语义正确率。因果或预测不能从趋势图自动生成事实。

## 正式解析任务与版本

新增持久化任务与当前解析指针。任务冻结 document_id、SHA、base parse_id、页面、旋转、解析模式、OCR 模型指纹或视觉连接版本。网络/模型调用在数据库事务之外执行。

状态：queued、running、completed、failed、cancelled、interrupted；显示实际阶段、页数、错误和耗时。支持取消和重试，重启后进行中任务标中断。后台并发受限；任务最多 40 页、900 秒，图片边长和像素、OCR 行数、响应大小及视觉调用数均有明确上限。超出规模要求分批，不静默截断。

只有页面处理和校验结束，且当前 SHA、归档状态、基础解析、连接/模型版本与取消状态都仍匹配，才在最终短事务中保存不可变 parse、激活指针并更新资料库质量。取消、超时、原件替换、归档、模型变化或坏响应均不得发布迟到结果。

保存后提交 RAG 索引；检索状态同时比较 SHA 与 active parse_id。统一 layout、预览、冻结、向量发布对当前解析的选择，修复原有“同 SHA 新解析仍显示索引就绪”的缺口。历史 parse 不删不改。

## 隐私与来源定位

本地 OCR 不外发。正式视觉解析采用十分钟、一次使用的预览，展示文档/版本、具体页码、图片数和发送字节、连接及实际服务范围。每页发送前后复核隐私、连接启用/测试/版本及资料状态，预览变化必须重做。

来源包括原件 SHA、parse_id、页/逻辑节、范围摘要、提取方法和原页 bbox，或 DOCX 包内部段落/单元格/chart 身份。客户端不能注入自己的 parse 或模型结果。页面层区分字符定位、OCR 行定位和结构区域定位；原件文字身份与识别结果一致性分别展示。

私人上传、会话、任务库、连接、密钥、OCR 缓存和模型调用记录不进入交接包。只交付公开模型与公开合成验收材料。服务仍仅监听 127.0.0.1:8765，业务数据库只读保护保持有效。

## 界面与接口

导入增加 DOCX/WEBP。文档工作台提供正式解析入口、页/范围选择、本机 OCR/结构视觉模式、主动模型安装、发送预览、真实任务进度、取消/重试及新旧解析对照。

阅读区显示 DOCX 逻辑节、结构表格/图表、原图及定位高亮，OCR 文字可选取；来源注明实际方法。既有临时视觉补充入口保留其待复核属性。宠物状态与真实任务对应。

拟增 `/api/document-processing` 配置、模型状态/安装、预览、任务创建、查询、取消和重试接口；现有 `/api/documents/{id}/layout/pages/reparse` 兼容保留。字段以实现中的严格 schema 为准，文档同步最终接口。

## 验证与交付

保护既有 Unicode 范围、重复文本歧义、坏固定范围不回退、SHA 篡改拒绝、旋转坐标、历史解析及 RAG 冻结/只读数据库回归。

新增公开合成 DOCX（标题、合并/嵌套表、图片、原生图表）、原生/扫描/旋转/混合 PDF、跨页表以及有标签/缺标签图表。扫描样本必须真的含字，不能拿灰色图片替代 OCR。使用实际 CPU 模型执行并核对关键文字、数字和区域；视觉协议夹具只能证明协议保护，不作为真实视觉质量成绩。

测试正式任务完成 → 保存新解析 → 源定位 → RAG 新代次，以及取消、归档、替换、连接变化、重启和坏响应不得激活。分开记录功能通过、OCR 实测、视觉协议、真实视觉质量和完整平台运行。

大规模独立评估另需按文档划分样本，分别报告表格内容/结构/定位、跨页关系、数字/符号/单位、图表系列/轴配对、来源定位、答案和拒答、耗时及内存。当前合成样本不替代独立质量指标，论文分数不计作项目通过。

源码与 RAR 使用同一公开白名单；依赖分卷及模型包校验、RAR 完整性/实际解压/逐文件摘要、仓库 commit/tag/附件 SHA 均须完成。Release 说明保留 OCR/视觉、Windows/Mac 实际验证边界。
