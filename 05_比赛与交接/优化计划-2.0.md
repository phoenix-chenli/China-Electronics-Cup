# 证流下一阶段优化计划

规划日期：2026-10-10。基线为后端 0.7.0、20261010 压缩包中的前端 2.0。

以下保留制定计划时的判断及建议。制定当时未修改代码、安装模型或调用收费服务；后续用户已授权继续执行，并指定 TokenDance 接入、保留当前目录服务及将 Windows 实机验收留为待办。执行后的实际状态以 [当前进度](当前进度.md)、[评估结果](../03_测试验收/优化评估结果.md) 和 [待办](待办与优化.md) 为准。历史记录不重复累计为本轮成绩。

建议顺序：修好交付与状态提示 → 建立质量基线 → 提升陌生库和跨源问答 → 补齐文档复核 → 根据实测优化性能。沿用现有前端风格与后端接口，从实际失败用例推动修改。

## 1. 当前基础与明确缺口

已有可复用基础：会话任务、模型规划和有限工具执行、数据库只读保护、受保护 JOIN/聚合/CTE、Decimal 数值反证、混合检索与重排、不可变文档解析和引用、正式 OCR/视觉解析任务、取消重试、2.0 结果工作台与来源阅读。

| 本轮核查发现 | 依据 | 优先处理方式 |
|---|---|---|
| 当前打包脚本排除全部 Windows 依赖分卷，且没有合并步骤 | `01_程序代码/启动与打包/package_handoff.py` 第 16 行；对当前三个分卷调用 include 均返回 False | 修正打包策略，保留三个分卷或在临时目录合并完整 ZIP；校验解压后的依赖摘要 |
| 当前源码包没有 OCR/RAG 权重包 | `06_运行环境` 仅有 Windows_x64；模型提供器支持显式确认下载 | 区分源码包、便携依赖包和含模型交付；界面显示随包可安装、需下载、已安装和不可用的实际状态 |
| README 和开发说明仍混有旧前端信息 | README 引用已删除的交接包校验文件；开发说明仍提及旧开场、prism-knot、home-polish | 更新单份进度、说明、链接及版本边界；保留有效的接口与运行约定 |
| 数值核验提示合并了不同失败状态 | `frontend/src/workspace.tsx` 将 counter_check 非 passed 一律显示为“复算不一致” | 分开显示一致、不一致、资料不足未核验及其他实际状态 |
| 来源页简略过程统一使用成功图标 | `frontend/src/evidence.tsx` 的 source-process 片段 | 按事件状态显示运行、成功、失败和取消，未知耗时留空 |
| 固定冒烟用例不足以评价真实模型质量 | `backend/evaluation.py` 的五个固定问题主要按关键词判断；RAG 评估说明明确 160 问尚未完成真实主问答和人工质量评估 | 保留冒烟回归，另建真实模型、独立答案和来源审核的评测 |
| 文档标为待复核，但人工修改确认流程尚未形成 | 待办说明；正式解析记录中的 human_reviewed=False | 增加有来源、有版本的人工复核，避免待复核数字绕过保护进入答案 |

Windows 历史实机和 OCR 记录已有明确日期、版本与范围。下一版完整 BAT、干净缓存、移动目录和不同账户仍需实测；Mac 本机静态检查不能替代这些验收。

## 2. 第一批：交付可靠、使用状态清楚

目标：完整下载后能启动；开始提问前能知道当前数据和可用能力。

修改范围：启动与打包脚本、README/使用说明/三份接续说明，以及 `main.tsx`、`agent.tsx`、`workspace.tsx`、`evidence.tsx` 的相关状态展示。

- 修复分卷遗漏，保持交接包排除个人数据库、上传、会话和密钥。将“依赖文件存在且摘要正确”加入实际打包检查。
- 设置中区分文本问答模型、检索模型、OCR 和视觉服务。缺失时给出对应安装或配置入口，避免用户提交后才发现能力不可用。
- 提问框附近显示当前数据库/资料范围与执行模式。切换来源需要新建问答时明确提示；追问继续绑定服务端记录的来源。
- 统一失败与复核状态文案。来源覆盖、算术复算、语义支持和人工复核分别显示实际结果。
- 修复断链与旧说明，保留新版唯一开发入口。Mac 启动和停止脚本保持可执行权限。

完成条件：分发包解压后依赖哈希一致；当前平台启动、停止、重复启动和端口冲突行为正确；新版 Windows 单独记录待验收或实测范围；模型缺失、网络失败、取消和重试均给出可操作提示。

## 3. 第二批：先建立质量基线，再改能力

目标：确定系统主要在哪类问题上失分，能够比较修改前后效果。

修改范围：复用 `03_测试验收/自动测试/评估RAG.py` 和现有测试组织，补充独立问数、跨源、澄清与证据审核评测。

建议首批评测规模为 60 个数据库问题、60 个 RAG/跨源问题、20 个澄清与多轮场景。它们是开发建议，不是官方样本数要求，也不是现有测试成绩。预算不足可先取分层小样本定位问题，再扩大评测。

- 数据库覆盖 JOIN、聚合、嵌套、去重、空值、零分母、时间范围、同名字段和一对多放大。以独立 SQL 与业务口径为答案依据，不以 SQL 能执行判定正确。
- RAG 覆盖单文档、多文档、版本冲突、条件缺失、应拒答、部分可答与扫描资料。人工分别核对答案正确性、引用支持、答全和拒答合理性。
- 跨源覆盖查数据后找原因、查数据后应用文档规则、跨版本规则、表格与文档联合、缺失证据澄清等五类问题。
- 多轮场景检验至少连续五轮中的实体、时间、口径与来源保持，并覆盖新建问答及切换来源。
- 现有 160 问合成 RAG 集用作回归。另冻结未参与调试的独立材料；记录模型版本、配置、材料摘要和失败类型。调试后不得继续把同一调试集当独立成绩。

报告结果正确率、引用支持率、答案覆盖率、拒答误判、误拦截和 P50/P95 延迟；注明分母、失败和超时。仅检索分数、协议测试或模型自评不作为业务准确率。

官方初赛要求单表和单文档能力各至少十个客观用例；决赛复杂 NL2SQL 与多文档/多模态问答的最高评分档均为至少 90%。90% 是争取的目标，需要独立实测证明。

## 4. 第三批：强化陌生数据库、跨源推理与澄清

目标：从熟悉销售示例扩展到新业务资料，同时保留只读、预算和引用保护。

主要入口：`backend/agent.py`、`database_query.py`、`sql_guard.py`、`counter_check.py`、`rag_retrieval.py`、`rag_grounding.py`。

1. 精准表字段定位：按问题筛选候选表和字段，加入可确认的字段描述、别名和统计口径。少量样例值只在权限与隐私设置允许时读取。大量表时逐步检索结构；仍需通过现有字段与关联授权。
2. 关联与统计粒度：检查一对多放大、重复维度、缺失键与统计单位。把订单数、订单行数、客户数等口径变成可澄清信息。正确执行的错误 JOIN 也必须进入失败统计。
3. 跨源任务：依据依赖关系先取得对象，再检索相关文档和有效规则，最后计算并生成逐条依据。不同步骤的对象、时间、来源版本和单位保持一致；真实事件用于展示任务过程。
4. 通用澄清：从固定销售选项扩展到时间、实体、统计粒度、规则版本等缺项；允许自由文本补充，保留已经确定的条件。
5. 文档公式：从现有奖金场景扩展到具有原文依据的参数、公式、单位和适用条件。公式结构、参数及结果分别可定位；不确定时请求确认或拒算。

首个完整业务场景建议沿用“指定时期和地区的销售冠军 → 查适用激励规则 → 计算奖金 → 查项目复盘 → 展示每项依据”。随后用冻结的新问题和陌生库检验泛化。

验收：至少五类跨源问题；复杂 SQL 的独立结果核对；五轮上下文保持；没有依据的公式参数不进入计算。比较修改前后的准确率、误拦截和耗时，不承诺修改后自然达到 90%。

## 5. 第四批：证据阅读和文档人工复核

目标：用户能从结论快速回到固定版本的原文，并处理确实无法自动确认的内容。

主要入口：`frontend/src/evidence.tsx`、`document-processing.tsx`、`workspace.tsx`，以及后端 `documents.py`、`document_tasks.py` 和版本存储。

- 桌面阅读保留结论与原文对照；小屏提供明确返回入口并恢复滚动位置。引用高亮、页码/逻辑节、缩放与版本切换始终反映实际定位。
- 将“找到引用”“算术一致”“语义支持”“人工复核”作为独立状态展示；空白、未识别和零不能混淆。
- 待复核文字、单元格或图表关联可对照原图修改；写入新解析版本并记录修改范围、原值、新值、时间和操作者标识。历史引用继续指向旧版本。
- 修改后仅更新受影响索引；取消、解析失败或索引提交失败保留可恢复状态。
- 先做旋转、文字层缺失、乱码、低质量等可解释检测和页级修复，再根据评测决定是否需要更复杂的解析方法。

验收：错误数字可被发现并修正；未复核内容不能进入确认答案；历史问答不被新解析改写；窄屏、键盘和中文输入法的主流程可用。

## 6. 第五批：性能与交接

先按真实耗时定位检索、重排、模型调用、OCR、数据库和渲染的瓶颈，再针对性优化：模型与结构缓存、候选集压缩、增量索引、长列表分页、图表按需加载和相互独立步骤的有限并行。缓存键需要包含来源/解析/连接版本，避免返回过期证据。

决赛性能建议覆盖 1 千/1 万/10 万行和 10/100/500 页，按资源从较小规模开始；报告硬件、冷暖缓存、并发、P50/P95、失败和取消表现。规模来自官方示例，不强制同时跑齐所有组合。

交付验收再覆盖 Windows 10/11 x64 干净环境与 Mac 原生环境，包含中文空格路径、移动目录、首次启动、离线可用范围、模型缺失、端口占用及保存恢复。只读保护、引用版本、目录深度与隐私排除规则继续保留。

完成后生成一份当前交接包及对应摘要。源码和模型交付的说明分别准确，历史验证不重复累计为新版成绩。

## 7. 竞赛投入与首批执行范围

建议优先形成官方第 3 项语义校验与澄清、第 4 项精准表定位、第 5 项多表 NL2SQL 的独立证据；再做实第 6 项文档公式、第 9 项文档质量。第 6 项的 6a、6b 合为一项；OCR 存在不自动证明第 9 项已攻克。

首批实际修改建议只覆盖第一批和第二批的小样本基线。评测定位主要错误后，再选择第三批中的两项主攻能力。每批均交付代码、受影响的回归/实际操作证据、独立结果核对和剩余限制。

更多装饰动画、语音入口、新数据库适配器、大规模框架替换和额外代理编排暂列后续。正式报告、PPT 和投稿发布按后续用户指定范围单独开展。
